# Проверка вариантов объяснения

Работай с брифом, полным контекстом участника и текущим сценарием. В этом проекте входы лежат в input, формат данных описан в system/exercise-data.md. Главный передаёт абсолютный корень проекта и run_id.

Для каждого выбираемого фрагмента:

1. Сформулируй различие, которое участник должен увидеть: например, узнаваемые буквы в адресе против реального домена назначения. Не подменяй анализ оценкой «выглядит подозрительно».
2. Сопоставь правильное объяснение с конкретным наблюдаемым фактом и известным участнику правилом. Если факт скрыт или отсутствует, верни дефект сценария.
3. Для каждого неверного варианта назови реальное заблуждение и факт, который его опровергает. «Очевидно неправильный» не подходит как обоснование дистрактора.
4. Попытайся защитить каждый неверный вариант, используя только показанный контекст. Если он тоже обоснован, перепиши набор. Не считай участника неправым из-за формулировки, допускающей два прочтения.
5. Прочитай варианты без письма. Если ключ угадывается по длине, осторожному тону, терминологии, грамматике или нелепости соседей, перепиши. Сохрани сопоставимую конкретность и длину.
6. Проверь обратную связь отдельно к каждому варианту. Она должна объяснять ошибку рассуждения и давать опору для повторной попытки. Не ограничивайся «неверно, попробуйте ещё».
7. Для нейтрального фрагмента объясни предел вывода. Отсутствие самостоятельного признака не подтверждает подлинность всего письма.
8. Проверь распределение правильных позиций и совпадение ключей во всех файлах.

Выход — options-review-vN.md или содержательный отчёт контролёра. Для каждой проблемы укажи ID, цитату, почему ответ угадывается/двусмыслен и что исправить. Итог PASS допустим только после чтения каждого набора, а не по наличию трёх вариантов в JSON.

Автоматический system/tools/check-exercise.py проверяет структуру, но не способен подтвердить правдоподобность и однозначность.

# Данные упражнения: версия контракта 1

Методист создаёт JSON. Сборщик переносит этот объект в window.EXERCISE в exercise-data.js без изменения смысла. Движок читает данные; ключи и учебный текст не зашиваются в app.js.

## Корень

- schema_version: число 1.
- run_id: строка phishing-01 или business-01; при новой отдельной попытке разрешён новый суффикс.
- version: строка v1, v2 и далее.
- title: непустая строка.
- context: непустая строка со всеми необходимыми фактами.
- instruction: короткая инструкция.
- email: объект ниже.
- fragments: массив семи объектов — четыре target=true и три target=false.
- summary: объект с непустыми intro и next_action; необязательное rewritten_email — улучшенное письмо для второго запуска.

## email

sender_name, sender_address, recipient, subject — непустые строки.
blocks — массив объектов в порядке письма:
- id: уникальная строка.
- kind: paragraph, link или signature.
- text: непустая строка, простой текст.
- fragment_id: строка ID соответствующего фрагмента или null для неанализируемого блока.

Ссылка в kind=link — учебный адрес, который показывается как текст и открывает только разбор. Никакого внешнего перехода. В приложении название действия «Подтвердить доступ» может быть оформлено как часть области ссылки, а адрес должен быть доступен без hover.

## fragments

- id: уникальная строка.
- location: sender, subject или block.
- block_id: ID блока для location=block; null в остальных случаях.
- target: true для искомого признака/проблемы, false для нейтрального наблюдения.
- evidence: конкретный факт, на котором основан вывод; рабочее поле, не показывать до ответа.
- question: вопрос к выбранному фрагменту.
- options: три объекта {id, text, correct, feedback}; id уникальны внутри набора, correct — boolean, ровно один true.
- takeaway: краткий правильный разбор для итогового просмотра.

Для sender и subject может быть по одному фрагменту. Для block связь двухсторонняя: block.fragment_id и fragment.block_id ссылаются друг на друга. Один фрагмент на один блок. Крупное смысловое предложение можно держать одним блоком.

Остальной текст не превращается в «ошибку» при клике. Все семь интерактивных областей имеют одинаковый нейтральный доступ, верные заранее не помечены.

## Состояние участника отдельно от данных

Сборщик хранит в памяти сессии по fragment_id:
- first_option_id: первый проверенный ответ или null;
- attempts: число нажатий «Проверить» с выбранным вариантом;
- resolved: получил ли участник правильное объяснение;
- current_option_id: текущий выбор, не равнозначный ответу;
- reviewed: открывался ли итоговый разбор после завершения.

Не менять options.correct в процессе. Не объявлять освоением простое открытие фрагмента. После завершения итоговый разбор не улучшает статистику первого прохождения. Сброс создаёт новое чистое состояние.

## Проверка

Запустить system/tools/check-exercise.py <путь к JSON>. Он ловит неверные связи, дубли ID, отсутствие ключей и обратной связи. Не проверяет педагогическую однозначность, истинность текста или браузер: для этого нужны оба навыка и контролёр.
